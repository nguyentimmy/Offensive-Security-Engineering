# 🧪 Validation Walkthrough — T1562.001: Impair Defenses — Disable or Modify Tools


### 📖 Why it matters

Blinding the defender is the classic pre-attack move — disable AV, add an exclusion, stop the security service, and everything that follows runs unmonitored. Ransomware, infostealers, and hands-on-keyboard operators all do some version of this before the main event. It's also one of the highest-fidelity detections you can build: legit admins rarely turn off Defender in production, so any tampering is a strong signal.

**Tactic:** Defense Evasion
**Technique:** [T1562.001 — Impair Defenses: Disable or Modify Tools](https://attack.mitre.org/techniques/T1562/001)

### ⚔️ The Atomic Tests

We validate three tests spanning the three attack angles — kill it, weaken it, or override it:

| # | Test | Platform | What it does |
| --- | --- | --- | --- |
| 1 | Disable Defender real-time protection | Windows | Turns off Defender's real-time monitoring via `Set-MpPreference` |
| 2 | Add Defender path exclusion | Windows | Adds an exclusion so files in a specified path are ignored by Defender |
| 3 | Disable Defender via registry policy | Windows | Sets the `DisableAntiSpyware` policy key to disable Defender at the policy level |

---
### 🔬 Test 1 — Disable Defender real-time protection

The direct approach — flip real-time monitoring off with a single PowerShell cmdlet. Loud, immediate, and one of the most-abused Defender-tampering patterns in the wild. If tamper protection is enabled and enforced, this command should be blocked outright.

**Attack commands** (`powershell`, elevated):

```powershell
Set-MpPreference -DisableRealtimeMonitoring $true
```

**Cleanup:**

```powershell
Set-MpPreference -DisableRealtimeMonitoring $false
```

---
### 🔬 Test 2 — Add Defender path exclusion

The sneakier variant. Don't disable Defender — just tell it to ignore a specific folder. The AV keeps humming along on everything except the attacker's chosen directory, which is much less likely to trip a "Defender disabled" alert than Test 1. A common evasion move before staging a payload in `\Temp\`.

**Attack commands** (`powershell`, elevated):

```powershell
Add-MpPreference -ExclusionPath "C:\Windows\Temp"
```

**Cleanup:**

```powershell
Remove-MpPreference -ExclusionPath "C:\Windows\Temp"
```

---

### 🔬 Test 3 — Disable Defender via registry policy

The registry-level override. Setting the `DisableAntiSpyware` policy key disables Defender through the same mechanism as GPO — bypasses any cmdlet-based detection that only watches `Set-MpPreference`. Validates whether your detection catches the underlying registry write, not just the PowerShell path.

**Attack commands** (`command_prompt`, elevated):

```cmd
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender" /v DisableAntiSpyware /t REG_DWORD /d 1 /f
```

**Cleanup:**

```cmd
reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender" /v DisableAntiSpyware /f
```

---

### ✅ What to validate after running

Confirm your detections surface:

- **Defender tamper events:** `DeviceEvents` with `ActionType` in `AntivirusScanCancelled`, `AntivirusDefinitionsUpdateFailed`, or explicit tamper-attempt events; Defender operational log **Event ID 5001** (real-time protection disabled).
- **PowerShell cmdlet use:** script-block logs (**Event ID 4104**) matching `Set-MpPreference`, `Add-MpPreference`, or `Remove-MpPreference`.
- **Registry policy writes:** `DeviceRegistryEvents` on `HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\DisableAntiSpyware` — Event ID **4657** on the raw Windows side.

**Did all three tests fire?** If Test 3 (registry) slipped past a PowerShell-only detection, add a rule on the registry write path.

> 💡 Any single tamper action can be an admin troubleshooting; the malicious pattern is **stacking** — real-time protection off, an exclusion added, and a service stopped, all within a short window. Enable **Defender Tamper Protection** to block most of this at the source, and detect on the tamper events for anything that gets through.
