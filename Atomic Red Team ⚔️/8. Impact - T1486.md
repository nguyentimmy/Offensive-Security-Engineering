# 🧪 Validation Walkthrough — T1486: Data Encrypted for Impact


### 📖 Why it matters

Ransomware is the endgame — encrypt everything valuable, drop a note, demand payment. By the time the note appears on the user's screen, the damage is done. That's why detection has to fire on the **encryption burst itself**, not on the note that follows — and validating coverage here is the highest-stakes exercise in the whole kill chain.

**Tactic:** Impact
**Technique:** [T1486 — Data Encrypted for Impact](https://attack.mitre.org/techniques/T1486)

### ⚔️ The Atomic Tests

We validate three tests that exercise the two core signals your detection should catch — bulk encryption from one process, and the ransom note that follows:

| # | Test | Platform | What it does |
| --- | --- | --- | --- |
| 1 | GPG bulk encryption | Windows / Linux | Uses `gpg` to encrypt a directory of files with a passphrase |
| 2 | 7-Zip password-protected archive | Windows | Archives files with `7z` and a password — mimics Cl0p-style archive-then-encrypt |
| 3 | Drop a ransom note | Windows | Writes a ransom note (`README`, `HOW_TO_DECRYPT`) to disk |

---
### 🔬 Test 1 — GPG bulk encryption

The direct pattern. `gpg` is a signed, legitimate encryption tool — and exactly what an attacker reaches for when they want to encrypt user data without dropping their own ransomware binary. Running it against every file in a directory produces the classic **encryption burst**: one process, many files, converging on a single new extension (`.gpg`). This is the exact pattern your Mass File Encryption detection is built to catch.

**Attack commands** (`powershell`):

```powershell
Get-ChildItem "C:\Users\Public\Documents" -Recurse -File | ForEach-Object {
    gpg --batch --yes --passphrase "AtomicTest" -c $_.FullName
}
```

**Cleanup:**

```powershell
Get-ChildItem "C:\Users\Public\Documents" -Recurse -Filter *.gpg | Remove-Item -Force
```

---
### 🔬 Test 2 — 7-Zip password-protected archive

The archive-then-encrypt variant. Ransomware families like **Cl0p** don't always drop a full crypto payload — sometimes they just bulk-archive user data into password-protected `.zip` or `.7z` files, then delete the originals. Same functional impact (victim can't access data), different file-event pattern.

**Attack commands** (`command_prompt`):

```cmd
7z a -pAtomicTest -mhe=on C:\Users\Public\Documents\stolen.7z C:\Users\Public\Documents\*
```

**Cleanup:**

```cmd
del C:\Users\Public\Documents\stolen.7z /f /q
```

---

### 🔬 Test 3 — Drop a ransom note

The impact indicator. Ransomware drops a note (`README.txt`, `HOW_TO_DECRYPT.html`, `RESTORE_FILES.txt`) into every folder it touched so the victim knows how to pay. A single note is noise — the tell is the same file dropped across many folders in a short window by one process.

**Attack commands** (`powershell`):

```powershell
$folders = Get-ChildItem "C:\Users\Public\Documents" -Recurse -Directory
foreach ($f in $folders) {
    "Your files have been encrypted. Contact recovery@example.test to recover." | Out-File "$($f.FullName)\HOW_TO_DECRYPT.txt"
}
```

**Cleanup:**

```powershell
Get-ChildItem "C:\Users\Public\Documents" -Recurse -Filter HOW_TO_DECRYPT.txt | Remove-Item -Force
```

---

### ✅ What to validate after running

Confirm your detections surface:

- **Encryption burst:** `DeviceFileEvents` showing one process modifying/renaming/creating many files across many folders in a short window, converging on a single new extension.
- **Ransom note drop:** `DeviceFileEvents` showing a file matching ransom-note patterns (`readme`, `how_to_decrypt`, `restore_files`) created across ≥ 3 folders by one process.
- **Process context:** `DeviceProcessEvents` for `gpg.exe`, `7z.exe`, or `powershell.exe` as the initiating process behind the file events.

**Did all three tests fire?** If Test 2 (7-Zip) didn't fire on your Mass File Encryption detection, tune the extension-convergence logic to include archive extensions (`.7z`, `.zip`, `.rar`) as an encryption signal.

> 💡 Precision comes from the **combination**: one process **+** many files **+** many folders **+** converging on one new extension. Legit bulk activity (installers, backup agents, OneDrive) touches many *different* extensions across many files; ransomware converges on one. That distinction is what keeps a detection precise enough to **auto-isolate on** — because minutes matter, and by the time a human reviews it, the share is gone.
